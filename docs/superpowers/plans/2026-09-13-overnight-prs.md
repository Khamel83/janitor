**Goal:** Publish Janitor documentation changes as reviewable PRs and preserve the original context, PR changes, and overnight review layers for a final human-directed agent review.

**Architecture:** A bounded GitHub CLI API adapter reads only already-published repository evidence and creates documentation-only commits through GitHub's Git database API. A separate read-only collector builds a local morning packet for all open PRs in the discovered owned repositories. The existing Homelab reviewer handles GitHub events without any changes.

**Tech Stack:** Python 3.10+, standard library, installed `gh`, existing Gateway2000 synthesis helper, pytest, existing Homelab systemd-to-Mac SSH runner.

## Global Constraints

- Never merge PRs, force-push, modify default branches, publish local WIP, execute target repository code, or change the reviewer service.
- Publish only CONTEXT.md and TODO.md sentinel sections from evidence already on the same GitHub repository; preserve text outside those sections. Never upload local paths, dirty files, branch inventories, or local context.
- Discover GitHub origin identities from the existing workspace and deduplicate owner/repo case-insensitively. Publishing is restricted to repositories owned by the authenticated GitHub user, with push permission, not forks or archived repositories.
- Default 20 new documentation PRs per invocation; explicit initial-pass limit up to 100, with a 100-PR rolling-24-hour ceiling. Keep one open proposal for overlapping Janitor documentation sections per repository; all independent code PRs still belong in the morning packet. Existing open PRs are left intact for review, including any reviewer or human changes. There is no PR count target or guarantee.
- All API calls have finite timeouts; all list endpoints paginate with an explicit upper bound and fail visibly when incomplete. No raw credential/API error bodies in logs. No API mutations or model calls in dry-run.
- No new model provider, reviewer, repair loop, budget subsystem, or notification service. Use existing extract_structured for bounded synthesis; stop publishing after three consecutive synthesis failures. Gateway2000 is the provider boundary.
- Local morning artifacts are private, atomic, timestamped snapshots plus latest pointers. Capture errors and stale/pending reviews as such, never as success. A final agent receives instructions to independently compare original intent, all PRs together, dependencies, and findings; recommendations only, no merge authority.

## Approved scope

The user wants layered work: original context -> Janitor changes in PRs -> existing automated review -> final agent recommendations about which PRs to merge or re-check. They explicitly want a larger initial pass and meaningful atomic PRs that preserve settled reasoning, followed by small incremental runs; no artificial splitting or new orchestration. Janitor remains a documentation caretaker, not an arbitrary project-TODO coding agent. A project can have several independent PRs, all reviewed together; overlapping generated CONTEXT/TODO updates stay one coherent proposal. Existing code PRs are collected alongside documentation PRs. Unpublished work branches stay local and can be read through the existing branch report; they are not auto-published. No changes are made to khamel-homelab-pr-reviewer.
